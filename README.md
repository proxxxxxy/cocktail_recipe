# ANTIGRAVITY — Cocktail Index

実在するスタンダードカクテル **141種類**（うちノンアルコールのモクテル15種類、IBA公認40種類）を、
手元の材料・名前・棚のボトルから引ける日本語のビジュアル・リファレンス。

公開先: <https://proxxxxxy.github.io/>

ビルド工程はありません。静的な HTML / CSS / JS 3枚がそのまま GitHub Pages に載っています。

---

## 動かす

```bash
python -m http.server 4173
```

<http://localhost:4173> を開くだけです。

## 画面

| モード | URL | 用途 |
| --- | --- | --- |
| 素材から | `#/` | ベースと割り材を選んでレシピに辿り着く |
| 名前から | `#/archive` | 全141種を検索・絞り込み |
| 手持ちから | `#/mybar` | 棚のボトルから「いま作れるもの」を出す |
| レシピ | `#/recipe/<slug>` | 1杯を直接開く共有リンク |
| **メニュー** | `#/menu/<code>` | ゲストに渡す、作れる杯だけの一覧 |

上部の3分割スイッチ（すべて / カクテル / モクテル）は全モードを横断します。
モクテル側ではアクセントカラーが真鍮から緑に変わります。

### メニューリンク

「手持ちから」の **メニューにして渡す** で発行します。棚の内容が URL に入っているので、
受け取った人の端末に何もなくても、ホストが実際に作れる杯だけが並びます。
ゲスト側はタブもビルド画面も出ず、章立て（はじめの一杯 / 食事とともに / 〆の一杯）で表示されます。

## 触る前に知っておくこと

この3つを破ると、静かに壊れます。テストがそれぞれを見張っています。

### 1. `SHELF_VOCABULARY` は末尾にしか足せない

`app.js` の `SHELF_VOCABULARY` は材料IDの並び順そのものが、
これまでに発行された**すべてのメニューリンクの意味**です。
1ビット＝1材料で URL に詰めているため、途中に挿入したり並べ替えたりすると、
配布済みのリンクが全部べつの棚を指します。**追加は必ず末尾へ。**

### 2. レシピキーの割り材はソート順に書く

キーは `ベース+割り材+割り材...` で、割り材は**アルファベット順**でなければいけません。
ビルド画面もルーティングもキーをその順で組み立て直すため、
順序が違うキーは誰からも辿り着けないレシピになります。

```js
"gin+lemon+soda+sugar"   // ✅
"gin+soda+lemon+sugar"   // ❌ 到達不能
```

### 3. 名前で紐づくリストがある

`SERVE_ORDER`（食前 / 〆）、`SEASONS`（春夏秋冬）、`GLASS_BY_NAME` はカクテル**名**で
データベースと結合しています。名前を変えるとき、あるいはこれらに書き足すときは、
綴りが一致していないと黙って外れます。

## ツール

```bash
node tools/gen-recipes.js          # recipes.md を app.js から再生成
node tools/gen-recipes.js --check  # 古ければ exit 1
node tools/stamp-version.js        # index.html の ?v= を中身のハッシュで打ち直す
node tools/stamp-version.js --check
```

`recipes.md` は **生成物** です。直接編集せず `app.js` を直してください。

`?v=` はキャッシュ避けです。スマホで見るとき、古いキャッシュは「直っていない」と
見分けがつかないので、`app.js` か `style.css` を触ったら必ず打ち直します
（`stamp-version.js` が中身から導出するので、手で数字を考える必要はありません）。

### セルフチェック

ページを開いた状態で、コンソールに貼ります。

```js
const s = document.createElement('script');
s.src = '/tools/selfcheck.js?t=' + Date.now();
s.onload = () => window.__selfcheck().then(r => console.log(r.summary, r.failures));
document.head.appendChild(s);
```

62項目。上の3つの不変条件、全モードが**実際に画面に見えているか**、
カウントと表示枚数の一致、ルーティングの往復、メニューコードの符号化、
全カクテルのサムネイルが描けるか、日本語文の体裁までを見ます。

> 「見えているか」を `querySelectorAll` の件数で確かめてはいけません。
> `display:none` の中身も数えてしまい、実際にアーカイブ画面が丸ごと消えたまま
> リリースされたことがあります。`offsetParent` と `offsetHeight` で見ます。

## 中身の話

- **カクテル / モクテルの判定は書いていません。** ベースがノンアルコールで、
  アルコールの割り材が入っていなければモクテル、と `isMocktailKey()` が導きます。
  フラグの付け忘れで分類が狂うことがない代わりに、ベースの登録が正しいことが前提です。
- **飲む順番（食前 / 食事とともに / 〆）は手で名指ししています。** レシピからは導けないからです。
  食前酒が辛口や苦味なのは食欲を開かせるため、食後酒が甘く重いのは夜を締めるためで、
  どちらも26度でシェイクだったりします。データに差が出ません。
- **グラスは大半が氷から導けます。** 例外（シャンパンのフルート、モスコミュールの銅マグ、
  氷を入れないのにロックグラスのサゼラック）だけ `GLASS_BY_NAME` に書いてあります。
- **「最初に揃える5本」は総当たりで解いています。** 人気のベース2本＋割り材3本という
  近似は、2材料のハイボールが多いカクテル側でたまたま当たっていただけで、
  モクテルに当てると0杯を返しました。いまは5本で最も多くの杯が完成する組を探索し、
  結果は半分ごとに1度だけ計算して使い回します。
